# Experts21: the DIO expert team

This repository is a team of expert AI agents for **Dautel Intelligent Operations (DIO)**, an AI consulting and deployment firm in Boynton Beach, Florida, founded by J. Erich Dautel (the Chairman). The experts advise Erich on planning, opening and running the firm, and draft the work: research, proposals, contracts for attorney review, prices, designs, code, content and plans.

| `tools/` | The data the agents and skills are generated from, and the build |

## How to use the team

- **Ask one expert:** type `@agent-<name>` and the question, for example `@agent-business-attorney What should our MSA say about AI output we can't guarantee?`
- **Ask the whole team:** start with `@agent-orchestrator`. It decides which experts to bring in, runs them in parallel, and returns one combined answer with risks, next steps and owners, for example `@agent-orchestrator Should we take a $9,000 intake-agent build for a 12-attorney PI firm next month? Bring in the experts.`
- **If the orchestrator returns a ROUTING PLAN FOR THE MAIN SESSION** (it does when the runtime doesn't let a subagent call other subagents, for example when `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` is `1`): run every expert in the plan in parallel (one Agent call each, all in the same message) with its exact question, then send all of their answers to `orchestrator` in one message and ask it to combine them. Show the user the combined answer.
- **Plain requests work too.** When a question spans several areas and no expert is named, delegate it to `orchestrator`; when it clearly belongs to one expert, delegate to that expert.
- **A skill on its own:** type `/<skill-name>`, for example `/contract-review`, to run a method directly.
- More example prompts: `docs/how-to-talk-to-your-experts.md`.

## Rules for every session

1. **Decision rights.** Erich (Chairman) approves final deployments to customers and every financial transaction, and decides anything with financial or ethical considerations. Agents advise and draft; they never commit money, sign or deploy on his behalf.
2. **Employer boundary.** While Erich is employed at FPL/NextEra: no utility clients, no vegetation-management or line-clearance contractors, no known FPL/NextEra vendors, no competing work, and never employer time, equipment, data or confidential information. Flag anything near it; decline when unsure.
3. **Privacy lock. This repository is public.** Never commit a street address, personal phone or email, client confidential data, named prospect lists, credentials or secrets. Keep API keys in environment variables only.
4. **Evidence over claims.** No fake metrics or invented clients; cite sources with dates; label estimates.
5. **Fix first, then automate.** Don't design automation around a process that hasn't been checked.

## Changing the team

The files in `.claude/agents/`, `.claude/skills/`, `docs/expert-roster.md`, `docs/agent-brains.md` and the `README.md` in each knowledge folder are **generated**. Documents added to a knowledge folder are not; add them freely (this repository is public). To add or change an agent or a skill, edit `tools/team.py` (agents) or `tools/skills_*.py` (skills), then run:

```bash
python3 tools/build.py
```

```bash
python3 tools/build.py --check
```

Or ask `@agent-agent-builder` to do it. Never edit the generated files by hand: the next build overwrites them, and `--check` fails.
